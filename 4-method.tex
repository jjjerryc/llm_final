\section{Methodology (Optional)}
\label{section:algorithm}
Our pipeline has five steps. \textbf{(1) Establish baseline:} initialize the 4-bit Qwen2.5-3B-Instruct with one fixed five-class QLoRA adapter, verify mapping from generated category names to the five IDs in \texttt{classes.json}, and measure development macro F1. \textbf{(2) Prepare papers:} map each review to its paper, extract PDF text, clean obvious parsing artifacts, and segment into 256-token chunks with 32-token overlap in the initial setting. \textbf{(3) Retrieve:} apply the three input conditions, using BM25 with the review statement as the query and an initial common evidence-token budget of 1,024 tokens for the two evidence-bearing methods. \textbf{(4) Predict:} run one fixed classifier using greedy decoding (\texttt{do\_sample=False}, maximum 24 new tokens) across conditions; record failures rather than silently discarding instances. \textbf{(5) Analyze:} calculate macro/per-class F1, latency, token use, and qualitative error categories. If a classifier trained with one evidence format behaves inconsistently under the others, we will explicitly discuss distribution shift, avoid causal claims about retrieval quality, and consider matched retraining only as a documented extension.
